# `src/plugin/` — the BepInEx mod (C#)

The data-source half of NOXMFD: a BepInEx plugin that runs inside Nuclear Option, reads live
telemetry from the game, and serves it over local HTTP/SSE to the web frontend in
[`../web/`](../web/). It also receives commands back from the frontend (e.g. target select/deselect).

**Flow in one line:** `Plugin` boots → `MissionLifecycle` watches missions, and every frame also
polls `Keybinds` and drains `CommandDispatcher` itself — so HOTAS binds and commands work at the
main menu, not just in a mission → `TelemetryReader` reads the game each frame (with `AssetCapture`
for one-shot images and `TgpFeed` for the targeting-pod video, `HudDeclutter` hiding the native
HUD) → fills a `TelemetrySnapshot` → `TelemetryServer` streams it over SSE to the browser (including
SOI focus state) and routes browser `/command`s back through `CommandDispatcher`. `SpriteCapture` is
the shared encode primitive; `HudDeclutterConfig` configures.

| File | Responsibility |
|------|----------------|
| [Plugin.cs](Plugin.cs) | **Entry point.** The `BaseUnityPlugin` BepInEx loads: binds config (HUD declutter + countermeasure keybinds + network), applies `HarmonyPatches.Init()`, starts `TelemetryServer`, and spawns a persistent `MissionLifecycle` — working around a Unity 2022.3 quirk where BepInEx's own GameObject dies on the boot→MainMenu scene transition. |
| [MissionLifecycle.cs](MissionLifecycle.cs) | **Mission lifecycle host.** A `DontDestroyOnLoad` behaviour that polls `MissionManager.IsRunning`; spawns the `TelemetryReader` + `HudDeclutter` when a mission starts and tears them down (and resets the server) when it ends. Every frame, mission or not, it also runs `Keybinds.Poll()` and `CommandDispatcher.Drain()` — the reason keybinds (including SOI) and commands work at the main menu, before any aircraft exists. |
| [TelemetryReader.cs](TelemetryReader.cs) | **Per-frame telemetry engine.** Per-mission behaviour that scans the world — fast 10 Hz (position/heading/speed) + slow 1 Hz (`FindObjectsByType`, map metadata, loadout, failures) — builds the `TelemetrySnapshot` (units, parts, RWR, missile warnings, radar contacts, locked targets, faction forces, mission/objective state) and pushes it to the server, and drains the inbound command queue each frame. |
| [AssetCapture.cs](AssetCapture.cs) | **One-shot game-asset extraction.** Turns live game Sprites/cockpit widgets into PNG/JPEG (or a JSON layout) once per type/session and hands them to the server: the map image; unit/weapon/CM/missile-warning icons; vehicle, ship, building and HUD-category type icons; faction logos; and both airframe silhouettes — the top-down one (AVN) and the frontal one (AFM), whose pylon marker states it also reads back for the reader. Owns its dedupe sets + `StatusDisplay` reflection; exposes the cockpit failure-indicator GameObjects the reader polls. |
| [TgpFeed.cs](TgpFeed.cs) | **Targeting-pod camera feed.** The continuous capture of the game's `TargetCam`: GPU-downscale → async readback → JPEG → MJPEG push, lazily allocating buffers only while a TGP subscriber is connected. Owns its own cadence; the reader drives it via `Tick(dt)` and tears it down on destroy. |
| [SpriteCapture.cs](SpriteCapture.cs) | **Async sprite→PNG/JPEG primitive.** Shared encode pipeline used by `AssetCapture`: Blit → `AsyncGPUReadback` → background-thread encode, keeping the GPU readback and encode off the frame's critical path (a synchronous capture would freeze the main thread ~670 ms on map load). |
| [TelemetrySnapshot.cs](TelemetrySnapshot.cs) | **Data contract.** The plain struct carrying one frame's worth of state (world position, heading/speed/altitude, loadout, countermeasures, fuel/throttle/heat, part damage + failures, map metadata, visible units, faction colors, TGP/RWR/missile-warning state, radar contacts and the player's own pitbull missiles, TGT list toggles, BDF/PAL faction forces, AFM pylon markers, MIS/OBJ mission state). The shared vocabulary between reader and server. |
| [TelemetryServer.cs](TelemetryServer.cs) | **HTTP/SSE transport.** Static `HttpListener` on the configurable `Network.Port` (default 5005, background threads): serves the embedded web assets (with ETag caching), `/stream` (SSE telemetry, one shared serialized frame per snapshot), and the captured images — `/map`, `/icon`, `/weapon`, `/cm`, `/tgt-icon`, `/bdf-icon`, `/building-icon`, `/hud-cat-icon`, `/airframe` (+ `/airframe-layout`) and `/afm` — plus the `/tgp.mjpg` feed. Receives `POST /command`, validates, and queues it for the dispatcher. Binds all interfaces for LAN access, opening the Windows URL-reservation + firewall gates via `netsh` when elevated and the bind is denied (else falls back to localhost) — see [NETWORKING.md](../../NETWORKING.md). Also tracks every connected browser tab as an `MfdInstance` (keyed by connection, surviving duplicate cids) and owns the SOI focus state machine — target cid/pane, a versioned action counter, opt-in activation, never-jump-on-disconnect — broadcast in every SSE frame; `/soi-instances` is a diagnostic dump of the live registry (see [docs/keybinds-page.md](../../docs/keybinds-page.md)). |
| [CommandDispatcher.cs](CommandDispatcher.cs) | **Inbound command channel.** Defines the flat `CommandEnvelope` wire format (including a `cid`/`n` pair for commands that aren't tied to a `/stream` connection) and a handler table, one entry per browser-driven action: `target.select`/`target.deselect` (via the game's high-level `CombatHUD` methods, so cockpit side effects come for free); the `tgt.*` family (`set`/`only`/`reset`/`clear`/`clear-datalink`/`clear-stale`/`laser`/`hud`) driving the TGT page's list toggles — docs/tgt-page.md; `weapon.select` (delegates to `WeaponSelectors`' shared station sequence); `avn.toggle` (the 8 AVN systems — gear/radar/guns/eng/assist/nvg/lights/turret, gear/radar/eng through the game's networked `Cmd*` calls, the rest client-local); `hud.set`/`hud.mode`/`declutter.set` (HUD page options + `HudDeclutterConfig`); `soi.next`/`soi.prev`/`soi.panes` (drive `TelemetryServer`'s SOI focus ring); `master-arms.set`/`combat-mode.set` (the WPN page's ARM/SAFE and A/A·A/G controls, combat-mode routed through `Keybinds.SetCombatMode` so it gets the same weapon auto-switch as the physical bind — docs/radar-master-arms.md); and the `keybind.*` writes backing the KEY page — key/joystick/axis capture and clear, axis invert, background input, and the three `set-*-on-start` immersion toggles. `Drain()` runs queued commands on the main thread — from the reader during a mission, from `MissionLifecycle` otherwise. |
| [HudDeclutter.cs](HudDeclutter.cs) | **Native-HUD declutter.** Mission-scoped behaviour (rides with the reader) that hides native in-game HUD elements so the web MFD can replace them without on-screen clutter. Re-applies on a 0.5 s interval since the game rebuilds the HUD per aircraft spawn. |
| [HudDeclutterConfig.cs](HudDeclutterConfig.cs) | **Declutter config flags.** BepInEx `ConfigEntry` toggles (per-element: weapon/ammo, minimap, top boxes), persisted to `.cfg` and editable live in the F1 ConfigurationManager menu; read by `HudDeclutter` each tick. |
| [Keybinds.cs](Keybinds.cs) | **Gameplay keybind registry** (countermeasures, landing gear, weapon selectors, MAP, TGT, SOI, cursor, immersion — see [docs/keybinds-page.md](../../docs/keybinds-page.md)). One `BindDef` row per functionality — keyboard `ConfigEntry<KeyboardShortcut>` plus optional Rewired joystick/HOTAS button index with a per-bind stick number, persisted in the `.cfg` but hidden from the F1 menu (the `/keybinds` web page is the UI) — polled each frame from the persistent host. Most binds are edge-triggered; the cursor's four direction binds are held instead, and the two cursor axes are analog rows (`AddAxis`) rather than buttons. Binds split into `Drive` (needs a live aircraft) and `DriveFree` (must work with none, e.g. at the main menu); `Poll()` always runs `DriveFree` binds first, then `Drive` binds only if an aircraft exists. CM keys deploy directly via `CountermeasureManager.DeployCountermeasure`, bypassing the stock input's contested deploy trigger; gear keys are dedicated raise/lower via `Aircraft.SetGear` with the stock locked-state + airborne guards; weapon keys drive `WeaponSelectors`; the 5 `DriveFree` SOI keys (SOI Next/SOI Prev/Nav Up/Nav Down/Nav Select) drive `TelemetryServer`'s focus ring directly. The MAP (Follow, Zoom In/Out — docs/map-cursor.md), TGT (Next/Previous Target, Clear Datalink/Stale — docs/tgt-keybind-nav.md) and cursor binds are `DriveFree` too, and act on whichever display currently holds SOI by way of `TelemetryServer.MapAction`, so one physical bind serves every page that answers to it — a zoom key ranges the RDR page and scrolls a list page (docs/page-cursor.md). The immersion binds (docs/radar-master-arms.md) are dedicated Radar/Engine/Master Arms ON/OFF pairs plus tap/hold-to-ALL combat-mode binds (`PollTapHold`), driving `ImmersionState`/`HarmonyPatches`-enforced radar/engine/`WeaponManager.Fire` gating. Joystick capture is plugin-side: `ArmJoyCapture(id)` arms a bind, the next button pressed is written into it (already-held latched switches excluded; background input forced on while armed); `ArmAxisCapture(id)` is the analog counterpart for the two cursor axes, each with its own invert flag. |
| [WeaponSelectors.cs](WeaponSelectors.cs) | **Weapon soft selectors.** The engine behind the weapon keybinds: a remembered gun choice and a missile/bomb choice over the aggregated loadout entries, classified by the game's public `WeaponInfo` flags, further filtered by `ImmersionState.CombatMode` (docs/radar-master-arms.md) — a hardcoded air-to-air missile name list, since the game exposes no A/A vs A/G classification. Cycle keys select within their class (cross-class press recalls, in-class press advances, depleted entries skipped); fire keys are held-driven two-stage triggers (cross-class press switches without firing, then `WeaponManager.Fire()` per held frame). Also owns the shared station find/select sequence reused by `CommandDispatcher.WeaponSelect`, and feeds the WPN page's soft-selection outlines via the snapshot. |
| [ConfigurationManagerAttributes.cs](ConfigurationManagerAttributes.cs) | **F1-menu entry hints.** Minimal local copy of ConfigurationManager's attribute bag (matched by type name via reflection — soft dependency, no assembly reference). Carries `Browsable`, used to hide keybind entries from the F1 menu. |
| [ImmersionConfig.cs](ImmersionConfig.cs) | **Immersion on-start settings** (docs/radar-master-arms.md). Three persisted `ConfigEntry<bool>` toggles — Radar/Engine/Master Arms ON on start, all default `true` (the game's own behavior) — read by `ImmersionState.EnsureSpawnDefaults` each time a new aircraft spawns, and editable from the KEY page's own IMMERSION OPTIONS block (not the F1 menu, same as `Keybinds.cs`'s binds). |
| [ImmersionState.cs](ImmersionState.cs) | **Immersion runtime state** (docs/radar-master-arms.md). `MasterArmsOn` and `CombatMode` (All/AirToAir/AirToGround) — the two live flags `HarmonyPatches` and `WeaponSelectors` gate on. `EnsureSpawnDefaults(Aircraft)` resets both to `ImmersionConfig`'s on-start settings once per aircraft spawn (de-duped by reference so it doesn't refire every frame), called from `TelemetryReader.PushSnapshot()`. |
| [HarmonyPatches.cs](HarmonyPatches.cs) | **Harmony patches** (docs/radar-master-arms.md) — the one part of the mod that alters game behavior rather than just reading state or calling public APIs; see [SECURITY.md](../../SECURITY.md) for the disclosure. Three patches, `Harmony("com.roque.NOXMFD").PatchAll()`'d from `Plugin.cs`: a postfix on `Aircraft.OnStartClient` sets the local aircraft's `radar.activated` from `ImmersionConfig.RadarOnOnStart` (client-side, covers both built-in and hardpoint-mounted radar); a postfix on `Aircraft.OnStartServer` sets `NetworkIgnition` from `EngineOnOnStart` (server-only — see the dedicated-server gap noted in the plan doc); a prefix on `WeaponManager.Fire` returns `ImmersionState.MasterArmsOn`, blocking gun/missile/bomb fire outright (including the stock keybind) while Master Arms is off. Every patch gates on `GameManager.GetLocalAircraft` first, so none ever run against another player's or an AI's aircraft. |
