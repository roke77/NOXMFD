# `src/plugin/` — the BepInEx mod (C#)

The data-source half of NOXMFD: a BepInEx plugin that runs inside Nuclear Option, reads live
telemetry from the game, and serves it over local HTTP/SSE to the web frontend in
[`../web/`](../web/). It also receives commands back from the frontend (e.g. target select/deselect).

**Flow in one line:** `Plugin` boots → `MissionLifecycle` watches missions, and every frame also
polls `Keybinds` and drains `CommandDispatcher` and `ExtensionRegistry` itself — so HOTAS binds,
commands and extension commands work at the main menu, not just in a mission → `TelemetryReader`
reads the game each frame (with `AssetCapture` for one-shot images, `TgpFeed` for the targeting-pod
video, `AkfTracker` for the kill feed, `HudDeclutter` hiding the native HUD and `HudWaypointCue`
drawing the route bug) → fills a `TelemetrySnapshot` → `TelemetryServer` streams it over SSE to the
browser (including SOI focus state, `RouteStore`'s route library and `ExtensionRegistry`'s extension
slices) and routes browser `/command`s back through `CommandDispatcher`. `SpriteCapture` is the
shared encode primitive; `HudDeclutterConfig` and `RatesConfig` configure. `Api.cs`/
`ExtensionRegistry.cs` is the third-party extension surface (docs/extensions-api.md). `Stores/`
contains the waypoint/route library (`RouteStore.cs`, docs/hud-waypoint-indicator.md), the saved-shell
layout library (`LayoutStore.cs`, docs/layout-save-load.md), and the HUD-filter-preset library
(`HudPresetStore.cs`, docs/hud-presets.md) — all three read/write through the shared `JsonLite.cs`
parser.

| File | Responsibility |
|------|----------------|
| [Plugin.cs](Plugin.cs) | **Entry point.** The `BaseUnityPlugin` BepInEx loads: binds config (HUD declutter + countermeasure keybinds + network), applies `HarmonyPatches.Init()`, starts `TelemetryServer`, and spawns a persistent `MissionLifecycle` — working around a Unity 2022.3 quirk where BepInEx's own GameObject dies on the boot→MainMenu scene transition. |
| [MissionLifecycle.cs](MissionLifecycle.cs) | **Mission lifecycle host.** A `DontDestroyOnLoad` behaviour that polls `MissionManager.IsRunning`; spawns the `TelemetryReader` + `HudDeclutter` when a mission starts and tears them down (and resets the server) when it ends. Every frame, mission or not, it also runs `Keybinds.Poll()` and `CommandDispatcher.Drain()` — the reason keybinds (including SOI) and commands work at the main menu, before any aircraft exists. |
| [TelemetryReader.cs](TelemetryReader.cs) | **Per-frame telemetry engine.** Per-mission behaviour that scans the world — fast 10 Hz (position/heading/speed) + slow 1 Hz (`FindObjectsByType`, map metadata, loadout, failures) — builds the `TelemetrySnapshot` (units, parts, RWR, missile warnings, radar contacts, locked targets, faction forces, mission/objective state) and pushes it to the server, and drains the inbound command queue each frame. |
| [AkfTracker.cs](AkfTracker.cs) | **Kill feed / session stats** (docs/akf-page.md). A plain class owned by `TelemetryReader` (mission-scoped, so it resets on mission end), fed by `HarmonyPatches`' kill-message and best-effort weapon-attribution hooks: kill feed lines (all + player-only), per-category kill counts, rank, and funds gained/spent. |
| [AssetCapture.cs](AssetCapture.cs) | **One-shot game-asset extraction.** Turns live game Sprites/cockpit widgets into PNG/JPEG (or a JSON layout) once per type/session and hands them to the server: the map image; unit/weapon/CM/missile-warning icons; vehicle, ship, building and HUD-category type icons; faction logos; and both airframe silhouettes — the top-down one (AVN) and the frontal one (AFM), whose pylon marker states it also reads back for the reader. Owns its dedupe sets + `StatusDisplay` reflection; exposes the cockpit failure-indicator GameObjects the reader polls. |
| [TgpFeed.cs](TgpFeed.cs) | **Targeting-pod camera feed.** The continuous capture of the game's `TargetCam`: GPU-downscale → async readback → JPEG → MJPEG push, lazily allocating buffers only while a TGP subscriber is connected. Owns its own cadence; the reader drives it via `Tick(dt)` and tears it down on destroy. Native mode reads `TargetCam.cam.targetTexture` directly; HQ mode (docs/tgp-high-quality-mode.md) reads from its own `TgpMirrorCam` instead. Owns only the capture/GPU pipeline — the client-side stat overlay data (mag/range/grid/target-detail, per-target lock boxes) it derives each tick lives in `TgpOverlay.cs` (`TgpFeed.Overlay`) instead. |
| [TgpOverlay.cs](TgpOverlay.cs) | **TGP stat overlay data** (docs/tgp-high-quality-mode.md). Mirrors `TargetScreenUI.UpdateTargetInfo` field for field — mag/range/grid/heading/altitude/speed, per-target lock boxes — which Native mode already gets baked into the video for free (the game's own stacked-camera UICam) but HQ mode's mirror camera does not, so `TgpFeed` derives it here every capture tick and the client renders it (`tgp.js`'s `applyOverlay`). |
| [TgpMirrorCam.cs](TgpMirrorCam.cs) | **HQ targeting-pod mirror camera** (docs/tgp-high-quality-mode.md). A second camera parented to `TargetCam`'s active mount, rendered every Unity frame (enabled + URP Base) at a higher resolution than the game's native TargetCam RT, used only when `TgpFeed.Quality != Native`. Never touches `TargetCam.cam`/its UICam/anything `CameraStateManager` owns — an independent camera rather than reparenting or overlaying the vanilla one. |
| [TgpManualControl.cs](TgpManualControl.cs) | **Manual TGP pointing state machine** (docs/tgp-manual-control.md). Keybind-driven pan/tilt/zoom over the game's real `TargetCam`, off by default, with Point Track, reset, manual COLOR/IR, lifecycle exits, and camera/mount state. Owns lifecycle and input state only; pure geometry lives in `TgpManualAimMath.cs`, private `TargetCam` access lives in `TgpManualTargetCamAccess.cs`, and native in-cockpit overlay drawing lives in `TgpNativeOverlay.cs`. |
| [TgpManualAimMath.cs](TgpManualAimMath.cs) | **Pure manual-TGP aim math.** BCL-only helper for azimuth/elevation conversion, FOV-scaled nudge, Zoom Axis mapping, and zoom scale. Linked into `tools/tests` so the geometry can be unit-tested without Unity/game references. |
| [TgpManualTargetCamAccess.cs](TgpManualTargetCamAccess.cs) | **Manual-TGP `TargetCam` private access.** Caches the reflected fields/methods manual control needs (`cam`, `currentMount`, `currentMode`, landing canvas, timeout, IR/exposure calls), keeping reflection fallback behavior in one place instead of scattering it through the state machine. |
| [TgpNativeOverlay.cs](TgpNativeOverlay.cs) | **Native in-cockpit manual-TGP overlay.** Populates the game's `TargetScreenUI` TextMeshPro fields and builds the manual crosshair/Point Track marker while `TgpManualControl` owns the underlying camera state. Separated from `TgpManualControl` so Unity UI patch concerns stay isolated. |
| [SpriteCapture.cs](SpriteCapture.cs) | **Async sprite→PNG/JPEG primitive.** Shared encode pipeline used by `AssetCapture`: Blit → `AsyncGPUReadback` → background-thread encode, keeping the GPU readback and encode off the frame's critical path (a synchronous capture would freeze the main thread ~670 ms on map load). |
| [TelemetrySnapshot.cs](TelemetrySnapshot.cs) | **Data contract.** The plain struct carrying one frame's worth of state (world position, heading/speed/altitude, loadout, countermeasures, fuel/throttle/heat, part damage + failures, map metadata, visible units, faction colors, TGP/RWR/missile-warning state, radar contacts and the player's own pitbull missiles, TGT list toggles, BDF/PAL faction forces, AFM pylon markers, MIS/OBJ mission state). The shared vocabulary between reader and server. |
| [TelemetryServer.cs](Http/TelemetryServer.cs) | **HTTP/SSE transport.** Static `HttpListener` on the configurable `Network.Port` (default 5005, background threads): owns endpoint handlers, streams `/stream` (SSE telemetry, one shared serialized frame per snapshot), serves captured images — `/map`, `/icon`, `/weapon`, `/cm`, `/tgt-icon`, `/bdf-icon`, `/building-icon`, `/hud-cat-icon`, `/airframe` (+ `/airframe-layout`) and `/afm` — plus the `/tgp.mjpg` feed. Receives `POST /command`, validates, and queues it for the dispatcher. Binds all interfaces for LAN access, opening the Windows URL-reservation + firewall gates via `netsh` when elevated and the bind is denied (else falls back to localhost) — see [NETWORKING.md](../../NETWORKING.md). Also tracks every connected browser tab as an `MfdInstance` (keyed by connection, surviving duplicate cids) and owns the SOI focus state machine — target cid/pane, a versioned action counter, opt-in activation, never-jump-on-disconnect — broadcast in every SSE frame; `/soi-instances` is a diagnostic dump of the live registry (see [docs/keybinds-page.md](../../docs/keybinds-page.md)). Owns the small remote-input state holders used by the optional browser keybind listener: same-PC detection on `/keybinds-config`, remote cursor vector/select expiry, and remote fire held-state expiry/min-press latching. |
| [TelemetryHttpRouter.cs](Http/TelemetryHttpRouter.cs) | **HTTP route dispatch.** Maps request paths to server endpoint handlers or embedded web assets, keeping the `HttpListener` accept loop separate from the URL table. |
| [TelemetryAssets.cs](Http/TelemetryAssets.cs) | **Embedded web asset serving.** Resolves files baked from `src/web/` into the DLL, serves `/assets/...` and direct page routes with build-scoped ETags, and owns the MIME/content-type mapping also reused by extension static responses. |
| [Api.cs](Api.cs) | **Public extension API** (docs/extensions-api.md). The intended integration surface for a third-party mod with a hard `BepInDependency` on NOXMFD — register a page (`RegisterExtension`), publish telemetry into the 10 Hz frame or a high-rate SSE event (`PublishSlice`/`PublishEvent`), and push an MJPEG feed (`PushMjpegFrame`). The opposite direction from `McBridge.cs`/`RcBridge.cs`'s reflection soft-dependency pattern (NOXMFD depending on a mod that's never heard of it). Thin delegating wrapper; `ExtensionRegistry` holds the actual state. |
| [ExtensionRegistry.cs](ExtensionRegistry.cs) | **Extension bookkeeping.** Backs `Api.cs`: the registered-extension table (id → asset resolver + command handler), published slices/events, per-id MJPEG state, and the inbound command queue — drained each frame from `MissionLifecycle.Update()` alongside `CommandDispatcher.Drain()`, so an extension's `/ext/<id>/command` works at the main menu too. `TelemetryServer` reads it for routing and frame serialization. |
| [CommandDispatcher.cs](CommandDispatcher.cs) | **Inbound command channel.** Defines the flat `CommandEnvelope` wire format (including a `cid`/`n` pair for commands that aren't tied to a `/stream` connection, plus `x`/`y` for remote cursor state) and a handler table, one entry per browser-driven action: `target.select`/`target.deselect` (via the game's high-level `CombatHUD` methods, so cockpit side effects come for free); the `tgt.*` family (`set`/`only`/`reset`/`clear`/`clear-datalink`/`clear-stale`/`laser`/`hud`) driving the TGT page's list toggles — docs/tgt-page.md; `weapon.select` plus remote-keybind helpers `weapon.cycle`, `cm.deploy`, `gear.set`, and `avn.set`; `avn.toggle` (the 8 AVN systems — gear/radar/guns/eng/assist/nvg/lights/turret, gear/radar/eng through the game's networked `Cmd*` calls, the rest client-local); `cursor.set`/`cursor.select` and `fire.set` feeding `TelemetryServer`'s remote held-state holders; `hud.set`/`hud.mode`/`declutter.set` (HUD page options + `HudDeclutterConfig` — the former two also feed `HudCombatModeFilters`' idle-only baseline capture, issue #50); `soi.next`/`soi.prev`/`soi.panes`/`soi.action` (drive `TelemetryServer`'s SOI focus ring and focused-surface actions); `map.action` (focused page cursor/navigation actions); `master-arms.set`/`combat-mode.set` (the WPN page's ARM/SAFE and A/A·A/G controls, combat-mode routed through `Keybinds.SetCombatMode` so it gets the same weapon auto-switch as the physical bind — docs/radar-master-arms.md); the `keybind.*` writes backing the KEY page — key/joystick/axis capture and clear, axis invert, background input, and the three `set-*-on-start` immersion toggles; `rates.set` (`RatesConfig`'s live-adjustable rate/quality settings, driving the MAP CFG and TGP CFG pages); the 13-entry `wpt.*` family (create/rename/delete/set-active/clear/reset/import a route, rename/reorder/reset/remove a waypoint, cycle/step, add-waypoint) driving `RouteStore`; `layout.save`/`.rename`/`.delete` driving `LayoutStore` (issue #51 — LOAD itself is client-side, reading `GET /layout-options` and applying entirely in the browser); and `preset.save`/`.rename`/`.delete`/`.load` driving `HudPresetStore` (issue #50 follow-up — `save` always targets whichever slot is server-side current, never a client-picked index). `Drain()` runs queued commands on the main thread — from the reader during a mission, from `MissionLifecycle` otherwise. |
| [RouteStore.cs](Stores/RouteStore.cs) | **Waypoint/route library** (docs/hud-waypoint-indicator.md, Option 2). Plugin-lifetime (not mission-scoped) single source of truth for the whole route library — every `wpt.*` command mutates it, every browser reads the same `RoutesJson`, and `AdvanceIfNear` (ticked at 1 Hz from `TelemetryReader`) advances the active route's progress independent of which page is open. Persists to `com.roque.NOXMFD.routes.json` beside the `.cfg`, read via `JsonLite`. |
| [JsonLite.cs](JsonLite.cs) | **Minimal JSON value reader.** `ponytail:` scoped to exactly the shapes `RouteStore`/`LayoutStore`/`HudPresetStore` need — object/array/string/number/bool/null, no `\uXXXX` escapes, no exponents, no schema validation. Written from scratch since no JSON parser exists anywhere else in this codebase and Unity's `JsonUtility` is unreliable for nested objects in this Mono runtime. Its own `SelfCheck()` (called from `Plugin.Awake` via `TryBind`) is the repo's one precedent for testing pure, non-game-object-dependent logic without a C# test runner — `HudPresetStore.SelfCheck()` follows the same shape. |
| [LayoutStore.cs](Stores/LayoutStore.cs) | **Saved shell layouts** (issue #51, docs/layout-save-load.md). Plugin-lifetime, arbitrary-count named list (`SaveLayout`/`RenameLayout`/`DeleteLayout`, dedup via `UniqueName`) — unlike `RouteStore`/`HudPresetStore`, a layout's `DataJson` is opaque to this store: the browser's own serialized arrangement, stored/returned as an escaped JSON-string field since it never needs re-parsing server-side. Persists to `com.roque.NOXMFD.layouts.json`, read via `JsonLite`. |
| [HudDeclutter.cs](HudDeclutter.cs) | **Native-HUD declutter.** Mission-scoped behaviour (rides with the reader) that hides native in-game HUD elements so the web MFD can replace them without on-screen clutter. Re-applies on a 0.5 s interval since the game rebuilds the HUD per aircraft spawn. |
| [HudDeclutterConfig.cs](HudDeclutterConfig.cs) | **Declutter config flags.** BepInEx `ConfigEntry` toggles (per-element: weapon/ammo, minimap, top boxes), persisted to `.cfg` and editable live in the F1 ConfigurationManager menu; read by `HudDeclutter` each tick. |
| [HudWaypointCue.cs](HudWaypointCue.cs) | **In-game HUD waypoint cue** (docs/hud-waypoint-indicator.md, design A). Mission-scoped behaviour, created alongside `HudDeclutter`, that draws a bug on the native heading tape plus a two-line readout, reading the active waypoint from `RouteStore`. The mod's first *additive* HUD change (every other HUD toucher only hides existing components); built entirely from untextured Images so it ships no art. |
| [RatesConfig.cs](RatesConfig.cs) | **Live-adjustable refresh rates** (MAP CFG + TGP CFG pages, `rates.set`). Hidden `ConfigEntry` values — TLM Hz (`TelemetryReader`'s fast tick), TGP Hz (`TgpFeed`'s interval) and TGP quality (native/hq, `TgpFeed.Quality`) — same shape as `HudDeclutterConfig`; a write lands straight in the reader's/feed's own field, live immediately. |
| [Keybinds.cs](Keybinds.cs) | **Gameplay keybind registry** (countermeasures, landing gear, weapon selectors, MAP, TGT, SOI, cursor, immersion — see [docs/keybinds-page.md](../../docs/keybinds-page.md)). One `BindDef` row per functionality — keyboard `ConfigEntry<KeyboardShortcut>` plus optional Rewired joystick/HOTAS button index with a per-bind stick number, persisted in the `.cfg` but hidden from the F1 menu (the `/keybinds` web page is the UI) — polled each frame from the persistent host. Most binds are edge-triggered; the cursor's four direction binds are held instead, and the two cursor axes are analog rows (`AddAxis`) rather than buttons. Binds split into `Drive` (needs a live aircraft) and `DriveFree` (must work with none, e.g. at the main menu); `Poll()` always runs `DriveFree` binds first, then `Drive` binds only if an aircraft exists. CM keys deploy directly via `CountermeasureManager.DeployCountermeasure`, bypassing the stock input's contested deploy trigger; gear keys are dedicated raise/lower via `Aircraft.SetGear` with the stock locked-state + airborne guards; weapon keys drive `WeaponSelectors`; the 5 `DriveFree` SOI keys (SOI Next/SOI Prev/Nav Up/Nav Down/Nav Select) drive `TelemetryServer`'s focus ring directly. The MAP (Follow, Zoom In/Out — docs/map-cursor.md), TGT (Next/Previous Target, Clear Datalink/Stale — docs/tgt-keybind-nav.md) and cursor binds are `DriveFree` too, and act on whichever display currently holds SOI by way of `TelemetryServer.MapAction`, so one physical bind serves every page that answers to it — a zoom key ranges the RDR page and scrolls a list page (docs/page-cursor.md). The optional remote keybind listener feeds `Poll()` as another held source for cursor and fire actions, merged with physical keyboard/HOTAS state before the same `TelemetryServer` cursor setters and `WeaponSelectors` fire methods run. The immersion binds (docs/radar-master-arms.md) are dedicated Radar/Engine/Master Arms ON/OFF pairs plus tap/hold-to-ALL combat-mode binds (`PollTapHold`), driving `ImmersionState`/`HarmonyPatches`-enforced radar/engine/`WeaponManager.Fire` gating. Joystick capture is plugin-side: `ArmJoyCapture(id)` arms a bind, the next button pressed is written into it (already-held latched switches excluded; background input forced on while armed); `ArmAxisCapture(id)` is the analog counterpart for the two cursor axes, each with its own invert flag. |
| [CmReflection.cs](CmReflection.cs) | **Shared countermeasure-station reflection.** One cached `FieldInfo`/`MethodInfo` pair into `CountermeasureManager`'s private station list and each station's `GetFirstCountermeasure()`, called by both `TelemetryReader.GetSelectedCmCategory` (reads the active station's category) and `Keybinds.IndexOfCategory` (searches for the station matching a requested category) — the reflection access lives here once; each caller's own read-one-vs-search-many logic stays put. |
| [WeaponSelectors.cs](WeaponSelectors.cs) | **Weapon soft selectors.** The engine behind the weapon keybinds: a remembered gun choice and a missile/bomb choice over the aggregated loadout entries, classified by the game's public `WeaponInfo` flags, further filtered by `ImmersionState.CombatMode` (docs/radar-master-arms.md) — a hardcoded air-to-air missile name list, since the game exposes no A/A vs A/G classification. Cycle keys select within their class (cross-class press recalls, in-class press advances, depleted entries skipped); fire keys are held-driven two-stage triggers (cross-class press switches without firing, then `WeaponManager.Fire()` per held frame). Also owns the shared station find/select sequence reused by `CommandDispatcher.WeaponSelect`, and feeds the WPN page's soft-selection outlines via the snapshot. |
| [ConfigurationManagerAttributes.cs](ConfigurationManagerAttributes.cs) | **F1-menu entry hints.** Minimal local copy of ConfigurationManager's attribute bag (matched by type name via reflection — soft dependency, no assembly reference). Carries `Browsable`, used to hide keybind entries from the F1 menu. |
| [ImmersionConfig.cs](ImmersionConfig.cs) | **Immersion on-start settings** (docs/radar-master-arms.md). Four persisted `ConfigEntry<bool>` toggles: Radar/Engine/Master Arms ON on start (all default `true`, the game's own behavior) — read by `ImmersionState.EnsureSpawnDefaults` each time a new aircraft spawns — plus `HudFiltersOnCombatMode` (default `false`, issue #50 follow-up), read by `HudCombatModeFilters` on every combat-mode change. All four editable from the KEY page's own IMMERSION OPTIONS block (not the F1 menu, same as `Keybinds.cs`'s binds). |
| [ImmersionState.cs](ImmersionState.cs) | **Immersion runtime state** (docs/radar-master-arms.md). `MasterArmsOn` and `CombatMode` (All/AirToAir/AirToGround) — the two live flags `HarmonyPatches` and `WeaponSelectors` gate on. `EnsureSpawnDefaults(Aircraft)` resets both to `ImmersionConfig`'s on-start settings once per aircraft spawn (de-duped by reference so it doesn't refire every frame), called from `TelemetryReader.PushSnapshot()` — the `CombatMode` reset goes through `Keybinds.SetCombatMode`, not a bare field write, so a respawn mid-A/A or A/G still restores the player's HUD baseline (issue #50). |
| [HudCombatModeFilters.cs](HudCombatModeFilters.cs) | **HUD filter automation on combat mode** (issue #50), gated off by default on `ImmersionConfig.HudFiltersOnCombatMode`. Entering A/A or A/G force-loads that HUD mode tab's own saved preset (`HUDOptions.listModes[A2A]`/`[A2G]`, the same preset a manual tab click would apply, and re-forced on a repeat press even without a mode change); returning to idle restores a running snapshot of the player's own HUD filter values instead. The snapshot updates on every `hud.set`/`hud.mode` command (`CommandDispatcher`) but only while combat mode is idle, so edits made mid-A/A or A/G don't overwrite it; `TelemetryReader`'s 1 Hz tick bootstraps it from whatever's live the first time `HUDOptions` exists, regardless of the setting. Driven entirely through `Keybinds.SetCombatMode` — reacts to mode transitions, never reads input itself. Also holds a second, short-lived snapshot (`CaptureBeforeSwitch`/`UndoNativeAutoToggleIfOff`) taken right before every combat-mode switch and restored right after when the toggle is off — undoes the game's own native `HUDOptions.AutomaticToggle`, which `WeaponSelectors`' unconditional weapon auto-switch (issue #32) can trigger regardless of this feature's setting (docs/radar-master-arms.md). |
| [HudPresetStore.cs](Stores/HudPresetStore.cs) | **HUD filter presets** (issue #50 follow-up, docs/hud-presets.md) — a separate feature from the row above: 5 fixed, player-named slots (not an arbitrary list like `LayoutStore`), capturing/restoring the same `HUDOptions` categories/vehicles/buildings arrays directly (no opaque client blob needed — this is server-owned game state). `Save`/`Rename`/`Delete`/`LoadPreset`; `LoadPreset` also pokes `HudCombatModeFilters.CaptureIfIdle()` since loading a preset counts as a player edit for that feature's own idle baseline. Persists to `com.roque.NOXMFD.hud-presets.json`; `SelfCheck()` round-trips the disk JSON, the one pure slice of this store. |
| [HarmonyPatches.cs](HarmonyPatches.cs) | **Harmony patches** (docs/radar-master-arms.md, docs/tgp-manual-control.md) — the one part of the mod that alters game behavior rather than just reading state or calling public APIs; see [SECURITY.md](../../SECURITY.md) for the disclosure. Includes spawn defaults, Master Arms fire gating, AKF attribution hooks, and manual-TGP gates for `TargetCam.Update`/`AimCamera` plus the `TargetScreenUI.UpdateTargetInfo` native-overlay prefix. Patches gate on local-player/manual-mode state before changing behavior. |
