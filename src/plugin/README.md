# `src/plugin/` — the BepInEx mod (C#)

The data-source half of NOXMFD: a BepInEx plugin that runs inside Nuclear Option, reads live
telemetry from the game, and serves it over local HTTP/SSE to the web frontend in
[`../web/`](../web/). It also receives commands back from the frontend (e.g. target select/deselect).

**Flow in one line:** `Plugin` boots → `MissionLifecycle` watches missions, and every frame also
polls `Keybinds` and drains `CommandDispatcher` and `ExtensionRegistry` itself — so HOTAS binds,
commands and extension commands work at the main menu, not just in a mission → `TelemetryReader`
reads the game each frame (with `AssetCapture` for one-shot images, `TgpFeed` for the targeting-pod
video, `AkfTracker` for the kill feed, `HudDeclutter` hiding the native HUD, `HudWaypointCue`
drawing route/steer guidance, `HudTgpCue` showing manual TGP line of sight, and `HudTtiCue` showing a
time-to-impact estimate for the focused locked target) → fills a
`TelemetrySnapshot` → `TelemetryServer` streams it over SSE to the
browser (including SOI focus state, `RouteStore`'s navigation library and `ExtensionRegistry`'s extension
slices) and routes browser `/command`s back through `CommandDispatcher`. `SpriteCapture` is the
shared encode primitive; `HudDeclutterConfig` and `RatesConfig` configure. `Api.cs`/
`ExtensionRegistry.cs` is the third-party extension surface (docs/extensions-api.md). `Stores/`
contains the route/steer-point library (`RouteStore.cs`, docs/steer-points.md), the saved-shell
layout library (`LayoutStore.cs`, docs/layout-save-load.md), the HUD-filter-preset library
(`HudPresetStore.cs`, docs/hud-presets.md), the Target Designator overlay (`TdStore.cs`,
docs/target-designator.md), and the squad target-lock aggregation (`SquadTargetsStore.cs`,
docs/hud-squad-target-marks.md) — all five read/write through the shared `JsonLite.cs` parser.
Separately, `Squadron.cs` (Steam P2P transport) + `Squad.cs` (the leader/member protocol on top of
it) + `PlayerRoster.cs`/`Presence.cs` (who's invitable) + `SquadEndpoint.cs` form the squad feature
(docs/squadron-transport.md) — `MissionLifecycle` drains `Squadron`/`Squad`/`Presence` every frame
the same way it drains `CommandDispatcher`/`ExtensionRegistry`, so squad traffic flows at the main
menu too. `SquadTargets.cs` + `Hud/HudSquadTargetMark.cs` (issue #49) sit on top of that same squad
state to broadcast/render who's targeting what.

| File | Responsibility |
|------|----------------|
| [Plugin.cs](Plugin.cs) | **Entry point.** The `BaseUnityPlugin` BepInEx loads: binds config (HUD declutter + countermeasure keybinds + network), applies `HarmonyPatches.Init()`, starts `TelemetryServer`, registers static process-shutdown cleanup, and spawns a persistent `MissionLifecycle` — working around a Unity 2022.3 quirk where BepInEx's own GameObject dies on the boot→MainMenu scene transition. |
| [MissionLifecycle.cs](MissionLifecycle.cs) | **Mission lifecycle host.** A `DontDestroyOnLoad` behaviour that polls `MissionManager.IsRunning`; spawns the `TelemetryReader`, `HudDeclutter`, `HudWaypointCue`, `HudTgpCue`, `HudFocusMark`, and `Hud/HudSquadTargetMark` (issue #49) when a mission starts and tears them down (and resets the server) when it ends. Every frame, mission or not, it also runs `Keybinds.Poll()`, `CommandDispatcher.Drain()`, and the squad transport's own drain (`Squadron.Poll()` → `Squad.Drain()`/`Presence.Drain()`) — the reason keybinds (including SOI), commands, and squad traffic all work at the main menu, before any aircraft exists. |
| [TelemetryReader.cs](TelemetryReader.cs) | **Per-frame telemetry engine.** Per-mission behaviour that scans the world — fast 10 Hz (position/heading/speed) + slow 1 Hz (`FindObjectsByType`, map metadata, loadout, failures) — builds the `TelemetrySnapshot` (units, parts, RWR, missile warnings, radar contacts, locked targets, faction forces, mission/objective state) and pushes it to the server, and drains the inbound command queue each frame. |
| [AkfTracker.cs](AkfTracker.cs) | **Kill feed / session stats adapter** (docs/akf-page.md). A plain class owned by `TelemetryReader` (mission-scoped, so it resets on mission end), fed by `HarmonyPatches`' kill-message and best-effort weapon-attribution hooks. It resolves live game units/HQ/local-aircraft state, then delegates feed/tally/funds/rank bookkeeping to `AkfTrackerLogic`. |
| [AkfTrackerLogic.cs](AkfTrackerLogic.cs) | **Pure AKF bookkeeping.** Generic-over-id state machine for kill feed lines (all + player-only), per-category player kill counts, rank, funds gained/spent deltas, capped feed retention, and weapon-attribution TTL lookup. Linked into `tools/tests` without Unity/game references. |
| [Assets/AssetCapture.cs](Assets/AssetCapture.cs) | **One-shot game-asset extraction.** Turns live game Sprites/cockpit widgets into PNG/JPEG (or a JSON layout) once per type/session and hands them to the server: the map image; unit/weapon/CM/missile-warning icons; vehicle, ship, building and HUD-category type icons; faction logos; and both airframe silhouettes — the top-down one (AVN) and the frontal one (AFM), whose pylon marker states it also reads back for the reader. Owns its dedupe sets + `StatusDisplay` reflection; exposes the cockpit failure-indicator GameObjects the reader polls. |
| [TgpFeed.cs](TgpFeed.cs) | **Targeting-pod camera feed.** Continuous capture of the game's `TargetCam`: GPU downscale → async readback → one bounded background JPEG worker → MJPEG push. LOW reads the native 360×240 texture; MID and HIGH use `TgpMirrorCam` at 720×480 and 1080×720. A single pending-frame slot drops stale work instead of accumulating latency, and generation checks prevent frames from an old mission or setting from publishing after a change. Owns only the capture/GPU pipeline — client-side stat overlay data lives in `TgpOverlay.cs`. |
| [TgpOverlay.cs](TgpOverlay.cs) | **TGP stat overlay data** (docs/tgp-high-quality-mode.md, docs/tgp-manual-control.md, docs/tgp-extended-quality.md). `Populate()` mirrors `TargetScreenUI.UpdateTargetInfo` field for field for a locked target — mag/range/grid/heading/altitude/speed, per-target lock boxes — which Native resolution already gets baked into the video for free (the game's own stacked-camera UICam) but the MID/HIGH mirror camera does not, so `TgpFeed` derives it here every capture tick and the client renders it (`tgp.js`'s `applyOverlay`). `PopulateManual()` is the no-lock counterpart, called instead whenever `TgpManualControl.ManualMode` is on — shares its numbers with the in-cockpit overlay via `TgpManualControl.ComputeOverlaySample`, so the web TGP page gets the same manual-mode data regardless of resolution. |
| [TgpMirrorCam.cs](TgpMirrorCam.cs) | **Higher-resolution targeting-pod mirror camera** (docs/tgp-high-quality-mode.md). A second camera parented to `TargetCam`'s active mount and rendered every Unity frame (enabled + URP Base) for the MID and HIGH tiers. Never touches `TargetCam.cam`, its UICam, or anything `CameraStateManager` owns. `SetInfrared(bool)` is an opt-in local-Volume desaturation (docs/tgp-full-screen.md) used only by `TgpFullScreen` — `TgpFeed`'s own MID/HIGH web pipeline never calls it, keeping its existing CPU-grayscale IR handling unchanged. |
| [TgpFeedSettings.cs](TgpFeedSettings.cs) | **Pure TGP resolution/quality policy.** Maps native/mid/high to 360×240/720×480/1080×720 and JPEG low/mid/high to 30/50/90. Normalizes legacy `hq` to MID and provides the temporary native/hq compatibility alias. Linked into `tools/tests` without Unity references. |
| [TgpManualControl.cs](TgpManualControl.cs) | **Manual TGP pointing state machine** (docs/tgp-manual-control.md). Keybind-driven pan/tilt/zoom over the game's real `TargetCam`, off by default, with Area/Point Track, PAD Cursor Select handoff from either mode to a nearby real unit lock, reset, manual COLOR/IR, lifecycle exits, and camera/mount state. Owns lifecycle and input state only; pure geometry lives in `TgpManualAimMath.cs`, private `TargetCam` access lives in `TgpManualTargetCamAccess.cs`, and native in-cockpit overlay drawing lives in `TgpNativeOverlay.cs`. |
| [TgpManualAimMath.cs](TgpManualAimMath.cs) | **Pure manual-TGP aim math.** BCL-only helper for azimuth/elevation conversion, FOV-scaled nudge, Zoom Axis mapping, and zoom scale. Linked into `tools/tests` so the geometry can be unit-tested without Unity/game references. |
| [TgpManualTargetCamAccess.cs](TgpManualTargetCamAccess.cs) | **Manual-TGP `TargetCam` private access.** Caches the reflected fields/methods manual control needs (`cam`, `currentMount`, `currentMode`, landing canvas, timeout, IR/exposure calls), keeping reflection fallback behavior in one place instead of scattering it through the state machine. |
| [TgpNativeOverlay.cs](TgpNativeOverlay.cs) | **Native in-cockpit manual-TGP overlay.** Populates the game's `TargetScreenUI` TextMeshPro fields and builds the manual crosshair/Point Track marker while `TgpManualControl` owns the underlying camera state. Separated from `TgpManualControl` so Unity UI patch concerns stay isolated. |
| [Tgp/TgpFullScreen.cs](Tgp/TgpFullScreen.cs) | **Cinematic full-screen TGP view** (issue #70, docs/tgp-full-screen.md). Its own `TgpMirrorCam` instance matched to `Screen.width`/`Screen.height` rather than a stretch of the small native instrument texture, shown on a dedicated `ScreenSpaceOverlay` canvas with a `TgpOverlay`-driven readout laid out in the same 4-corner grouping and white-on-translucent-black chip style as the web TGP page (`tgp.js`/`tgp.css`), plus the boresight crosshair/Point Track box while manual mode is active. Ticked every frame from `TelemetryReader` regardless of whether any browser page is open; auto-exits on aircraft loss, a landing-gear/cam conflict, or the pause menu/map opening. Bearing-needle rotation is `TgpFullScreenMath.cs`. |
| [Tgp/TgpFullScreenMath.cs](Tgp/TgpFullScreenMath.cs) | **Pure full-screen-TGP math.** One function today — the bearing-needle rotation formula, deliberately not `tgp.js`'s own `(bearing + 180)` since this needle is built with the opposite pivot/growth direction (docs/tgp-full-screen.md). BCL-only, linked into `tools/tests` so a future edit can't silently reintroduce the double-flip bug that formula caused once already. |
| [Assets/SpriteCapture.cs](Assets/SpriteCapture.cs) | **Async sprite→PNG/JPEG primitive.** Shared encode pipeline used by `AssetCapture`: Blit → `AsyncGPUReadback` → background-thread encode, keeping the GPU readback and encode off the frame's critical path (a synchronous capture would freeze the main thread ~670 ms on map load). |
| [TelemetrySnapshot.cs](TelemetrySnapshot.cs) | **Data contract.** The plain struct carrying one frame's worth of state (world position, heading/speed/altitude, loadout, countermeasures, fuel/throttle/heat, part damage + failures, map metadata, visible units, faction colors, TGP/RWR/missile-warning state, radar contacts and the player's own pitbull missiles, TGT list toggles, BDF/PAL faction forces, AFM pylon markers, MIS/OBJ mission state). The shared vocabulary between reader and server. |
| [TelemetryJson.cs](Telemetry/TelemetryJson.cs) | **Pure telemetry-frame serializer.** `Serialize(TelemetrySnapshot, ...)` builds the SSE frame's JSON string — no Unity/BepInEx/live-session references, taking SOI focus/immersion/extension-slice values as plain parameters instead of reaching for `TelemetryServer`/`ImmersionState`/`ExtensionRegistry` itself. Linked into `tools/tests` alongside `TelemetrySnapshot.cs` so the wire format is covered without a live game. |
| [TelemetryServer.cs](Http/TelemetryServer.cs) | **HTTP transport + server state.** Static `HttpListener` on the configurable `Network.Port` (default 5005, background threads): owns the shared serialized SSE frame cache consumed by `SseHub`, the TGP placeholder JPEG consumed by `TgpMjpegHandler`, and the HUD-options JSON snapshot consumed by `ConfigEndpoint`. Binds all interfaces for LAN access, opening the Windows URL-reservation + firewall gates via `netsh` when elevated and the bind is denied (else falls back to localhost) — see [NETWORKING.md](../../NETWORKING.md). Tracks every accepted request with path/remote/age diagnostics; cooperative shutdown cancels and aborts those contexts, waits boundedly for their handlers and the accept thread, then probes the configured port before reporting it released. Keeps thin facades over `SoiFocus` for existing call sites. |
| [SoiFocus.cs](Http/SoiFocus.cs) | **SOI focus + MAP cursor/action state.** Which display/surface (cid, pane) the SOI keys and PAD cursor drive — a versioned action counter, opt-in activation (the ring only appears once a SOI key is pressed), never-jump-on-disconnect — plus the MAP cursor vector/select and MAP view-action (Follow/Zoom) state that only makes sense relative to whichever surface holds SOI. Broadcast in every SSE frame (`SoiJson`) and the MAP cursor's own event (`CursorJson`). |
| [TargetFocus.cs](Http/TargetFocus.cs) | **Shared locked-target focus** (issue #62, docs/tgt-cycle-focus.md). A different concept from `SoiFocus` despite living beside it — this tracks WHICH TARGET, not which surface: the single locked id TGT/FCR/HSD describe/highlight everywhere at once. `Reconcile` keeps it valid as the game's own lock list changes (a kill, a fresh lock, a deselect); `Cycle` steps it for Next/Previous Target. Rides inside `TelemetrySnapshot` itself, so it needs no version counter of its own. |
| [TelemetryHttpRouter.cs](Http/TelemetryHttpRouter.cs) | **HTTP route dispatch.** Maps request paths to endpoint handlers or embedded web assets and returns each handler's completion `Task`, keeping request ownership in `TelemetryServer` rather than launching untracked stream work from the URL table. |
| [CapturedAssetEndpoint.cs](Http/CapturedAssetEndpoint.cs) | **Captured game-asset HTTP surface.** Owns the cached map image, unit/weapon/CM/TGT/BDF/building/HUD-category icons, airframe silhouettes/layouts, the transparent no-icon PNG, and the `/map`, `/icon`, `/weapon`, `/cm`, `/tgt-icon`, `/bdf-icon`, `/building-icon`, `/hud-cat-icon`, `/airframe`, and `/airframe-layout` endpoints. |
| [CommandEndpoint.cs](Http/CommandEndpoint.cs) | **Inbound command HTTP boundary.** Receives `POST /command`, enforces POST + JSON `Content-Type` + bounded body size, parses the flat `CommandEnvelope`, rejects unknown commands, and queues accepted commands for `CommandDispatcher` to drain on the Unity main thread. Also applies the same JSON/body hygiene to extension command posts before handing their opaque JSON bodies to `ExtensionRegistry`. |
| [CommandContentType.cs](Http/CommandContentType.cs) | **Content-Type check.** One `IsJson(contentType)` — strips a `;charset=...` suffix and compares case-insensitively — pulled out of `CommandEndpoint`'s `POST /command` gate so it's a plain, directly testable function; linked into `tools/tests` without any HTTP/Unity references. |
| [ConfigEndpoint.cs](Http/ConfigEndpoint.cs) | **Configuration/options HTTP surface.** Serves `/config`, `/keybinds-config`, `/hud-options`, `/wpt-options`, `/layout-options`, `/hud-presets`, and `/rates-config`. Owns request-local same-PC detection for remote keybind visibility and delegates persisted option JSON to the relevant stores/config classes. |
| [SquadEndpoint.cs](Http/SquadEndpoint.cs) | **Squad HTTP surface** (docs/squadron-transport.md, docs/target-designator.md). Serves `/squad` (`Squad.StateJson`), `/server-players` (`PlayerRoster.Json`, the SQD invite candidate list), and `/td-state` (`TdStore.StateJson`) — each a plain `{ready, state}`/prebuilt-string read, `ready` reflecting `Squadron.Ready` so a non-Steam launch answers honestly instead of failing silently. |
| [ExtensionEndpoint.cs](Http/ExtensionEndpoint.cs) | **Extension HTTP surface.** Serves `/ext-manifest`, routes `/ext/<id>` page/assets through the registered asset resolver, hands `/ext/<id>/command` to `CommandEndpoint`, and streams `/ext/<id>/feed.mjpg` from `ExtensionRegistry`'s per-extension MJPEG buffer. |
| [SseHub.cs](Http/SseHub.cs) | **SSE session hub.** Owns `/stream` connection lifetime, per-client `MfdInstance` registry keyed by connection, cid sanitizing/fallback ids, hello events, high-rate cursor events, the `sqd`/`td-state`/`wpt-options` snapshot events (latest-value-wins, same gating as cursor — docs/sse-push-refactor.md; `sqd`/`td-state` wrap `{ready,state}` matching their REST siblings, `wpt-options` bare), extension SSE events, and `/soi-instances` diagnostics. A leader-shared payload (route/steer-point sharing, `td.designate`) is applied directly by `Squad.HandleData` the instant it arrives, not relayed as its own SSE event — every display then sees the result through the `td-state`/`wpt-options` push above, same as any other plugin-side mutation. Calls back into `TelemetryServer` only for the shared telemetry frame and SOI disconnect release. |
| [TgpMjpegHandler.cs](Http/TgpMjpegHandler.cs) | **TGP MJPEG stream.** Owns `/tgp.mjpg`'s multipart response, live JPEG frame cache, placeholder-first cold-start behavior, per-client frame polling, cold-start diagnostics, and subscriber count used by `TelemetryServer.WantsTgpFrames` to gate `TgpFeed` capture work. |
| [TelemetryAssets.cs](Http/TelemetryAssets.cs) | **Embedded web asset serving.** Resolves files baked from `src/web/` into the DLL, serves `/assets/...` and direct page routes with build-scoped ETags, and owns the MIME/content-type mapping also reused by extension static responses. |
| [Api.cs](Extensions/Api.cs) | **Public extension API** (docs/extensions-api.md). The integration surface for a third-party plugin with a hard `BepInDependency` on NOXMFD: register a page (`RegisterExtension`), publish telemetry into the 10 Hz frame or a high-rate SSE event (`PublishSlice`/`PublishEvent`), and push an MJPEG feed (`PushMjpegFrame`). Thin delegating wrapper; `ExtensionRegistry` holds the actual state. |
| [ExtensionRegistry.cs](Extensions/ExtensionRegistry.cs) | **Extension bookkeeping.** Backs `Api.cs`: the registered-extension table (id → asset resolver + command handler), published slices/events, per-id MJPEG state, and the inbound command queue — drained each frame from `MissionLifecycle.Update()` alongside `CommandDispatcher.Drain()`, so an extension's `/ext/<id>/command` works at the main menu too. `ExtensionEndpoint` reads it for routing; `TelemetryServer` reads it for frame serialization. |
| [CommandDispatcher.cs](CommandDispatcher.cs) | **Inbound command channel.** Defines the flat `CommandEnvelope` wire format (including a `cid`/`n` pair for commands that aren't tied to a `/stream` connection, plus `x`/`y` for remote cursor state) and a handler table, one entry per browser-driven action: `target.select`/`target.deselect` (via the game's high-level `CombatHUD` methods, so cockpit side effects come for free); the `tgt.*` family (`set`/`only`/`reset`/`clear`/`clear-datalink`/`clear-stale`/`laser`/`hud`) driving the TGT page's list toggles — docs/tgt-page.md; `weapon.select` plus remote-keybind helpers `weapon.cycle`, `cm.deploy`, `gear.set`, and `avn.set`; `avn.toggle` (the 8 AVN systems — gear/radar/guns/eng/assist/nvg/lights/turret, gear/radar/eng through the game's networked `Cmd*` calls, the rest client-local); `cursor.set`/`cursor.select` and `fire.set` feeding `RemoteInputState`'s remote held-state holders; `hud.set`/`hud.mode`/`declutter.set` (HUD page options + `HudDeclutterConfig` — the former two also feed `HudCombatModeFilters`' idle-only baseline capture, issue #50); `soi.next`/`soi.prev`/`soi.panes`/`soi.action` (drive `TelemetryServer`'s SOI focus ring and focused-surface actions); `map.action` (focused page cursor/navigation actions); `master-arms.set`/`combat-mode.set` (the WPN page's ARM/SAFE and A/A·A/G controls, combat-mode routed through `Keybinds.SetCombatMode` so it gets the same weapon auto-switch as the physical bind — docs/radar-master-arms.md); the `keybind.*` writes backing the KEY page — key/joystick/axis capture and clear, axis invert, background input, and the three `set-*-on-start` immersion toggles; `rates.set` (`RatesConfig`'s live-adjustable rate/quality settings, driving the MAP CFG and TGP CFG pages); the `wpt.*` family (create/rename/delete/set-active/clear/reset/import a route or steer point, rename/reorder/reset/remove a waypoint, cycle/step, add-waypoint, add/rename/delete/set-active/cycle/import a steer point — docs/steer-points.md) driving `RouteStore`, plus its squad-share sub-group `.accept-shared`/`.reject-shared`/`.share` and their steer-point twins `.accept-shared-steerpoint`/`.reject-shared-steerpoint`/`.share-steerpoint` (accepting/rejecting a pending share and pressing SHARE are real browser actions; a leader's incoming `wpt.route`/`wpt.route-deleted`/`wpt.steerpoint`/`wpt.steerpoint-deleted` is applied directly by `Squad.HandleData`, not a browser command); the `sqd.*` family (`create`/`invite`/`set-callsign`/`accept`/`decline`/`leave`/`relinquish`/`disband`/`kick`/`send`) driving `Squad.cs` — peer SteamIDs are parsed and validated at this layer, the trust boundary, not inside `Squad` itself; the `td.*` family (issue #47, docs/target-designator.md) — `select`/`assign`/`clear`/`designate`/`member-clear`/`acquire-all` (an incoming `td.designate` is likewise applied directly by `Squad.HandleData`, not a browser command), every one reusing an existing envelope field rather than adding new ones, leader-only actions gated here via `Squad.IsLeader`; `layout.save`/`.rename`/`.delete` driving `LayoutStore` (issue #51 — LOAD itself is client-side, reading `GET /layout-options` and applying entirely in the browser); and `preset.save`/`.rename`/`.delete`/`.load` driving `HudPresetStore` (issue #50 follow-up — `save` always targets whichever slot is server-side current, never a client-picked index). `Drain()` runs queued commands on the main thread — from the reader during a mission, from `MissionLifecycle` otherwise. |
| [TargetSelectionPolicy.cs](TargetSelectionPolicy.cs) | **Pure enemy-visibility gate** (docs/jamming-contact-telemetry-hardening.md, F1/F3). `IsSelectable(factionKnown, ownRadarDetected, pictureJamActive)` closes the `target.select` id-enumeration exploit and — shared with `TelemetryReader.BuildRdr`'s datalink-only pass — encodes that an own-radar detection stays eligible during native picture jamming even though a plain faction-known/datalink track does not. `CommandDispatcher.TargetSelect` is the only caller that also applies it to command-driven selection; `TrySelectTarget` itself is intentionally left ungated so the manual TGP's own line-of-sight acquisition still works. Linked into `tools/tests` without Unity references. |
| [RemoteInputState.cs](Input/RemoteInputState.cs) | **Browser remote-input held state.** Holds the short-TTL remote cursor vector/select source, plus a named table of remote held-fire flags (gun/release/release-single/jammer-pod, cursor zoom-in/out — any string `Keybinds.cs` names, not a fixed set) with the minimum press window that keeps fast browser taps visible to `Keybinds.Poll()` for at least one Unity frame. |
| [RouteStore.cs](Stores/RouteStore.cs) | **Route and steer-point library** (docs/steer-points.md). Plugin-lifetime single source of truth for routes, waypoints, standalone steer points, selection priority, imports, and squad shares. Every browser reads the same `RoutesJson`; route-only `AdvanceIfNear` runs at 1 Hz independent of which page is open. Persists to `com.roque.NOXMFD.routes.json` beside the `.cfg`, read via `JsonLite`. |
| [Squadron.cs](Squad/Squadron.cs) | **Squad transport** (docs/squadron-transport.md). Generic small-text Steam P2P messaging (`SteamNetworkingMessages`, a distinct interface the game itself never touches) between two SteamIDs — knows nothing about squads/leaders/invites, only moves a versioned `{v,type,payload}` envelope reliably and in order, capped at 16 KB. Accepts a session from anyone (an invite has to reach a stranger before they can decide to join); every message TYPE's own trust is `Squad.cs`'s job, one layer up. `Ready` lazily/retry-safely detects Steam so a non-Steam launch just returns false forever. |
| [Squad.cs](Squad/Squad.cs) | **Squad protocol**, on top of `Squadron.cs`. Leader/member state machine, star topology (leader holds a session with every member; members never talk to each other): `CreateSquad`/`Invite`/`AcceptInvite`/`DeclineInvite`, single-squad-per-player enforcement (`sqd.conflict`/`sqd.poach`), `Leave`/`RelinquishLeadership`/`Kick`/`Disband`, callsigns, and the generic `SendData`/`SendDataTo` payload slot (route/steer-point sharing and `td.designate`, issue #47). Also relays `sqd.locks`/`sqd.locks-aggregate` (issue #49) into `SquadTargetsStore.cs` — the one place that actually calls `Squadron.SendTo`/`SendToAll`, so `SquadTargets.cs` never touches the transport directly. `CheckLiveness` (called alongside `PlayerRoster.Refresh()`) reuses `Presence.HasNoxmfd`'s TTL to detect a leader/member who crashed or force-quit with no graceful sqd.leave/kick/disband to send, and cleans them out locally. No persistence — resets on plugin restart by design. `StateJson` is the `/squad` response body. |
| [SquadTargets.cs](Squad/SquadTargets.cs) | **Squad target-lock broadcast, live-game glue** (issue #49, docs/hud-squad-target-marks.md). Ticked at 1 Hz from `TelemetryReader`'s slow scan, next to `Presence.Tick`/`PlayerRoster.Refresh`. Reads the local aircraft's `weaponManager.GetTargetList()`, and — only on a real change — tells `Squad.cs` to send (`SendLocks`) or relay (`RelayLocksAggregate`) the update. The Unity/Squad-touching half of the split `TdStore.cs`/`CommandDispatcher.TdAcquireAll` also keep between pure data and live-game access. |
| [PlayerRoster.cs](Squad/PlayerRoster.cs) | **Match roster for SQD's invite picker** (docs/squadron-transport.md). Reads `FactionHQ.GetPlayers` (the same source the game's own scoreboard uses, so no host privilege needed) once per 1 Hz slow scan, filtered to faction-mates `Presence.cs` confirms are actually running NOXMFD right now. Also builds an unfiltered SteamID→current-aircraft lookup (`AircraftFor`) SQD's roster table reads for every member's plane, self included, plus a SteamID→aircraft-`persistentID` lookup feeding `IsSquadAircraft` (issue #48, docs/map-squad-styling.md) — `TelemetryReader.BuildUnits` reads it per visible unit so MAP can tint a squadmate's icon teal, rebuilt fresh every tick from `Squad.SquadmateSteamIds()` so a squad ending or a member's aircraft changing needs no dedicated invalidation. |
| [Presence.cs](Squad/Presence.cs) | **"Who's running NOXMFD" beacon** (docs/squadron-transport.md). Every instance broadcasts a lightweight announcement to its whole faction roster every 5s over `Squadron.cs`'s shared transport (its own message type, its own drain cursor) and tracks a per-peer last-seen time with a 15s TTL — so `PlayerRoster`'s invite list only ever offers players who could actually receive and answer an invite, instead of a dead, never-timing-out `Squad.cs` invite reading as a bug. |
| [JsonLite.cs](JsonLite.cs) | **Minimal JSON value reader.** `ponytail:` scoped to exactly the shapes `RouteStore`/`LayoutStore`/`HudPresetStore` need — object/array/string/number/bool/null, no `\uXXXX` escapes, no exponents, no schema validation. Written from scratch since no JSON parser exists anywhere else in this codebase and Unity's `JsonUtility` is unreliable for nested objects in this Mono runtime. Its own `SelfCheck()` (called from `Plugin.Awake` via `TryBind`) is the repo's one precedent for testing pure, non-game-object-dependent logic without a C# test runner — `HudPresetStore.SelfCheck()` follows the same shape. |
